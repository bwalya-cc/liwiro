# Verse Heartbeat

Use this only for proactive review and scheduled system checks.

Checklist:
- Inspect current platform state relevant to the specialist's remit.
- Check the active page, target service, dataset, or runtime surface before drafting a proactive issue.
- Compare against known issue memory to avoid duplicate reminders.
- Only surface a user-facing issue when it is specific, material, and actionable.
- Prefer concise issue titles, stable issue keys, and direct opening messages.
- Distinguish active failure, latent risk, and suggested improvement instead of collapsing them into one severity.
- Include the concrete basis for the alert such as a failing service, missing config, blocked validation, or stale artifact.
