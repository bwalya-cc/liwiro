VDB Interfaces · Transport Guide

Choose the fastest safe transport for the host you are actually running on.

This guide reframes the old IPC comparison into a Liwiro-style operator reference. It is meant to support platform-aware startup, local performance decisions, and clearer expectations around when to use Unix sockets, named pipes, or localhost HTTP.

Fastest Local IPC Unix Socket

Best raw latency on Linux and macOS when the caller and VDB are on the same machine.

Windows Native IPC Named Pipe

Preferred local IPC on Windows when the integration path is same-host and not remote.

Most Portable HTTP

Easiest to debug and script across tools, but carries extra framing and TCP overhead.

Default Recommendation

What Liwiro should do

Linux / macOS → Unix socket Windows → Named pipe Cross-tool fallback → HTTP
  1. Detect the host from runtime OS signals, not the shell or terminal.
  2. Normalize impossible transport choices before startup reaches the interface layer.
  3. Cache detected platform and runtime tools only after a successful startup.
  4. Use local HTTP as the compatibility path when direct IPC is unavailable or intentionally bypassed.

For Liwiro specifically, this means a Windows Git Bash session still needs Windows transport behavior, while Linux and macOS keep the Unix socket path as the lowest-overhead local option.

Capability, latency, and operator fit

Host Mapping

Startup policy

  • Windows: prefer named pipes; if config says unixsocket, downgrade before startup.
  • Linux / macOS: prefer Unix sockets; if config says namedpipe, downgrade before startup.
  • HTTP: stay on HTTP when explicitly chosen or when tooling needs a portable fallback.

Design Takeaways

What matters most

  • Correctness beats preference: the wrong IPC mechanism should never be attempted for a host.
  • Cache after success: detection results are useful when startup completed cleanly, not before.
  • Ports should adapt: local HTTP services should roll to the next free port automatically.
  • Operator clarity matters: resolved transport and URLs should be printed in one consistent UI.

Scope

How to use this page

Treat this as an operator reference for VDB interface selection and startup behavior, not a marketing benchmark sheet. If the platform behavior changes, update this page alongside the startup scripts and transport normalization rules.
